1. Mit hová mentünk?

A böngészőben kétféle tárolás van, és más-más célra jó:

TárolásMire jóKorlát
localStorageKis szöveges adat: hot cue pontok, beállítások, kötésekKb. 5 MB, csak szöveg (JSON)
IndexedDBNagy adat: a zenei fájlok maguk, a könyvtárNagy méret, de aszinkron (várni kell rá)
Szabály: a zenei fájlt soha ne a localStorage-ba tedd. Oda csak kicsi szöveg fér, és a fájl ott sérül vagy nem fér el.

2. Fájl mentése az IndexedDB-be

Az IndexedDB egy beépített adatbázis a böngészőben. Ebbe bele lehet tenni a File objektumot is, így a zene a következő megnyitáskor is ott lesz. Az adatbázis megnyitása aszinkron, ezért Promise-t és async/await-et használunk:

function dbMegnyitas() {
  return new Promise((ok, hiba) => {
    const keres = indexedDB.open("partyDeck", 1);
    keres.onupgradeneeded = () => {
      // az első megnyitáskor létrehozzuk a "tracks" táblát
      keres.result.createObjectStore("tracks", { keyPath: "id", autoIncrement: true });
    };
    keres.onsuccess = () => ok(keres.result);
    keres.onerror = () => hiba(keres.error);
  });
}

async function fajlMentese(fajl) {
  const db = await dbMegnyitas();
  return new Promise((ok, hiba) => {
    const tranzakcio = db.transaction("tracks", "readwrite");
    tranzakcio.objectStore("tracks").add({ nev: fajl.name, meret: fajl.size, fajl: fajl });
    tranzakcio.oncomplete = () => ok();
    tranzakcio.onerror = () => hiba(tranzakcio.error);
  });
}

Az olvasás ugyanígy működik, csak readonly tranzakcióval, és a getAll() hívással az összes sort lekérjük.

Gyakori hiba: ha az IndexedDB-hez új táblát adsz, a indexedDB.open verziószámát növelni kell (1-ről 2-re), különben az onupgradeneeded nem fut le.

3. A lejátszási sor (queue): NEXT és AUTO

A lejátszási sor egy egyszerű tömb. A dalokat a végére tesszük, a NEXT pedig az elsőt veszi ki:

const sor = [];

function sorbaTesz(dal) {
  sor.push(dal);            // a tömb végére
}

function kovetkezo() {
  if (sor.length === 0) return null;
  return sor.shift();       // az első elemet kiveszi és visszaadja
}

Az AUTO működése: amikor egy dal véget ér, a program automatikusan a következőt indítja. Ehhez az ended eseményt figyeljük:

let auto = true;

zene.addEventListener("ended", () => {
  if (auto && sor.length > 0) {
    betoltEsIndit(kovetkezo());
  }
});
Tipp: a sort is elmentheted a localStorage-ba, de csak a dalok neveit és a fájlok azonosítóit. Maga a fájl az IndexedDB-ben marad, és az azonosító alapján újra betöltheted.

4. Hang előállítása és WAV export

A hangot számok sorozataként tároljuk. Egy hangérték -1 és 1 között van, a mintavételi frekvencia (például 44 100) azt adja meg, másodpercenként hány szám van. A WAV egy egyszerű formátum: egy 44 bájtos fejléc után a számok következnek, 16 bites egész formában.

function wavKeszit(adat, mintavetel) {
  const hossz = adat.length;
  const buffer = new ArrayBuffer(44 + hossz * 2);
  const view = new DataView(buffer);

  function iras(poz, szoveg) {
    for (let i = 0; i < szoveg.length; i++) {
      view.setUint8(poz + i, szoveg.charCodeAt(i));
    }
  }

  iras(0, "RIFF");
  view.setUint32(4, 36 + hossz * 2, true);
  iras(8, "WAVE");
  iras(12, "fmt ");
  view.setUint32(16, 16, true);            // a fejléc hossza
  view.setUint16(20, 1, true);             // 1 = nyers hang
  view.setUint16(22, 1, true);             // 1 csatorna (mono)
  view.setUint32(24, mintavetel, true);    // mintavételi frekvencia
  view.setUint32(28, mintavetel * 2, true);// bájt/másodperc
  view.setUint16(32, 2, true);             // blokk mérete
  view.setUint16(34, 16, true);            // bit/minta
  iras(36, "data");
  view.setUint32(40, hossz * 2, true);

  for (let i = 0; i < hossz; i++) {
    const s = Math.max(-1, Math.min(1, adat[i]));
    view.setInt16(44 + i * 2, s < 0 ? s * 0x8000 : s * 0x7FFF, true);
  }
  return new Blob([buffer], { type: "audio/wav" });
}

A true az utolsó paraméter a kis-endian sorrend. A WAV fájl ezt várja, ezért kell kiírni.

Letöltés

const url = URL.createObjectURL(wavKeszit(adat, 44100));
const a = document.createElement("a");
a.href = url;
a.download = "keveres.wav";   // a letöltendő fájl neve
a.click();
URL.revokeObjectURL(url);     // felszabadítjuk a memóriát

5. MP3 export a lamejs könyvtárral

Az MP3 tömörített formátum, ehhez egy kódolóra van szükség. A lamejs könyvtár ezt a LAME kódolót teszi elérhetővé a böngészőben. A könyvtár betöltése után így működik:

function mp3Keszit(adat, mintavetel) {
  const enc = new lamejs.Mp3Encoder(1, mintavetel, 192);   // 1 csatorna, 192 kbps
  const minta = new Int16Array(adat.length);
  for (let i = 0; i < adat.length; i++) {
    const s = Math.max(-1, Math.min(1, adat[i]));
    minta[i] = s * 0x7FFF;
  }

  const darabok = [];
  const blokk = 1152;                       // az MP3 kódoló ennyi mintánként dolgozik
  for (let i = 0; i < minta.length; i += blokk) {
    const kodolt = enc.encodeBuffer(minta.subarray(i, i + blokk));
    if (kodolt.length > 0) darabok.push(kodolt);
  }
  const vege = enc.flush();                 // a maradék kiírása
  if (vege.length > 0) darabok.push(vege);

  return new Blob(darabok, { type: "audio/mpeg" });
}
Miért 1152? Az MP3 kódoló egy-egy kötegben 1152 mintát dolgoz fel. Ha ennél több adatot adsz neki egyszerre, a kódoló nem működik megfelelően, ezért darabokra bontjuk.

6. Felvétel: MediaRecorder

Ha a keverést élőben szeretnéd rögzíteni, a MediaRecorder a jó eszköz. A hangot először egy createMediaStreamDestination csomópontba kell küldeni, mert a rögzítő adatfolyamot (stream) vár:

const cel = ctx.createMediaStreamDestination();
masterGain.connect(cel);                    // a fő hangerő kimenete a rögzítőhöz megy

const felvevo = new MediaRecorder(cel.stream);
const darabok = [];
felvevo.ondataavailable = (e) => darabok.push(e.data);
felvevo.onstop = () => {
  const felvetel = new Blob(darabok, { type: felvevo.mimeType });
  // ezt a Blobot letölthetjük vagy elmenthetjük az IndexedDB-be
};

felvevo.start();    // indítás
// később: felvevo.stop();

7. Offline alkalmazás: manifest és service worker

Az alkalmazás telefonon úgy működik, mint egy normál app: van ikonja, teljes képernyőn fut, és internet nélkül is megnyílik. Ehhez három dolog kell:

  • manifest.webmanifest: leírja a nevet, az ikont és a megjelenítési módot ("display": "standalone").
  • sw.js (service worker): a háttérben fut, és eltárolja a program fájljait a gyorsítótárba (cache).
  • Regisztráció: a fő oldal jelzi a böngészőnek, hogy ezt a fájlt használja.
// a fő oldalon
if ("serviceWorker" in navigator) {
  navigator.serviceWorker.register("sw.js");
}

// sw.js
const CACHE = "party-dj-v2";

self.addEventListener("install", (e) => {
  e.waitUntil(
    caches.open(CACHE).then((c) =>
      c.addAll(["./", "index.html", "manifest.webmanifest", "icons/icon-192.png", "icons/icon-512.png"])
    )
  );
});

self.addEventListener("fetch", (e) => {
  e.respondWith(
    caches.match(e.request).then((v) => v || fetch(e.request))
  );
});
Két gyakori hiba:
  • A service worker csak HTTPS-en (vagy helyi gépen) működik. Ezért kell a GitHub Pages címe.
  • Ha módosítod a fájlokat, de a CACHE nevét (például party-dj-v2-ről party-dj-v3-ra) nem változtatod, a telefon a régi, gyorsítótárazott verziót mutatja.

8. Teljes példa és feladatok

Az alábbi demóban egy lejátszási sort kezelhetsz. A Sorba adás gomb új, rövid hangot tesz a sorba, a NEXT az elsőt kiveszi, a sor pedig a böngészőben megmarad. A WAV letöltés a kiválasztott hangot WAV fájlba írja.

Lejátszás most: –
    Kész.
    1. feladat: Adj a sor minden eleméhez egy „×” gombot, amely törli az adott dalt. Ehhez a kiir() függvényben hozz létre egy gombot, és a kattintásnál a sor.splice metódussal távolítsd el az elemet.
    2. feladat: Írj egy AUTO kapcsolót: ha be van kapcsolva, a NEXT akkor is fusson le, amikor egy dal véget ér. Ehhez egy auto változót használj, és figyeld az ended eseményt.
    3. feladat (bónusz): Ha módosítod a sw.js fájlt, a telefon mégis a régit mutatja. Magyarázd el, miért, és mit kell változtatni, hogy a frissítés megérkezzen.
